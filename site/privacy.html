Privacy

Effective 12 November 2026. The revision history is at the end.

FactLot collects as little as it can. This notice covers factlot.com, the hosted API and MCP server at api.factlot.com, and paid plans. The open-source packages you run yourself make no network calls and send FactLot nothing.

What we collect

The website

factlot.com sets no cookies and uses no advertising, tracking or third-party analytics. FactLot's own server counts page views in totals only: how many requests each group of pages (for example the pricing page, or all property pages together) received in a day, and an estimate of how many distinct visitors there were, made from a one-way hash of the IP address that changes every day. The counts hold no IP address, no page a particular visitor opened and nothing that identifies or follows a visitor, and are deleted after 40 days. Its only scripts are two files under /try/. The first, on the Try a lookup page (/try/), does nothing until you press the button or open a link that carries an address (such as /try/?q=1200+Main+St, cut to at most 120 plain characters), then sends that address to FactLot's hosted API (see below), and stores nothing in your browser. The second, on the pricing, Try a lookup and MCP server pages, asks the hosted API whether the free key (see below) is offered and shows a link to it if so; it sends nothing you typed and stores nothing in your browser. Cloudflare, which hosts it, processes your IP address, browser user agent and the page you ask for, to deliver the page and protect the site from abuse. Cloudflare may keep request logs under its own privacy policy; FactLot keeps no access log of its own.

The hosted API

  • Usage records. For each request we record the time, the API key ID (the first 16 characters of a SHA-256 hash of the key, never the key itself, "free-key" for a free key, or "anonymous" when there is no key), the plan tier, the path, the HTTP method and the response status code. No IP address is recorded. These records are kept in a Cloudflare Workers Analytics Engine dataset.
  • Daily usage totals. We count requests and events in totals for each day: requests by page or route group, registry lookups by tool and by state or county prefix, refusals for a used-up quota or a plan limit, free answers that left earlier values out, checkouts started and completed, reports and model calls, each by kind of caller (no key, free connection, free key, Pro, Team). We also keep an estimate of how many distinct callers of each kind there were, as a fixed-size sketch built from values that are already hashes (the daily-changing hash of the IP address, a connection's ID, or the key ID); a sketch cannot be turned back into a list of callers. The totals hold no IP address, address searched, parcel, key or email, and are kept in Cloudflare Workers KV and, for events, in the Analytics Engine dataset.
  • Rate-limit counters. To enforce the per-minute limit, requests are counted per IP address on the Free plan and per key on paid plans, for the current one-minute window only.
  • Lookup quota counters. To enforce registry lookup quotas, lookups are counted for the current day on the Free plan, keyed by a hash of the IP address (for IPv6, of its /64 prefix), never the address itself, and per subscription for the current month on paid plans. Days and months are UTC. A counter is deleted when its window ends.
  • Report counters. To enforce the monthly report allowance, reports are counted for the current month, keyed by a hash of the IP address (for IPv6, of its /64 prefix), never the address itself, on the Free plan and per subscription on paid plans. Months are UTC. A counter is deleted when its month ends.
  • Report files. When you build a report with report_create, we store the generated file (an XLSX workbook, PDF or ICS calendar) for 24 hours so you can download it, then delete it. The file contains the figures and any text you passed (a title, citations, adjustment reasons). It is stored under a hash of the download link's random token, and nothing else about the request is stored. Anyone who has the link can download the file until it is deleted.
  • Error logs. When a request fails, the Worker logs only the error's name (for example TypeError), never its message or any request content.
  • Key records. For each paid key we store a SHA-256 hash of the key, the plan, the key's status, the Stripe customer and subscription IDs, the subscription status, the date the key was created, the time of the last subscription check, the time the key was revoked (revoked_at), whether a refund or payment dispute has put the key on hold, and the time a payment last failed (payment_failed_at).
  • Free key by email (optional). The Free plan works without a key. If you ask for a free key, at factlot.com/account or with POST /v1/keys/free, you give your email address and confirm that you accept the terms and this notice. We send one email to that address: a link that works once and expires after 30 minutes. It is a transactional message sent through Cloudflare Email Sending, and it contains the link and no key. We send no marketing email unless you tick the separate box for optional emails described below, and nothing else to that address because of this request except the deletion email described below if you ask for it. The address is used in memory to send the email and to make a hash of it; it is not written to storage, usage records or logs, except as described for the optional emails below if you tick that box. What we store instead is a hash of the address: SHA-256 of the lower-case address together with a secret that only FactLot holds. We treat that hash as personal information, because it is the same every time the same address is used. Opening the link only shows a button; pressing it creates the key, which is shown once. We then store a record of the key (a SHA-256 hash of the key, the address hash, the date it was created and, once the key is replaced, the time it was revoked) and, for each address hash, which key is its current one. One address has one active free key: a new key replaces the earlier one, which stops working. A link that is never used creates nothing and expires. Between asking and opening the link we keep a record of the link (a hash of its random ID, the address hash and its expiry) for 30 minutes, and a marker of the address hash for 5 minutes, so that one address gets at most one link email every 5 minutes. A marker that a link was used, held under a hash of its random ID and not linked to the address, is kept for 13 months so that the link cannot be used twice. The link is a web address that you open, so Cloudflare's request logs may hold it; it cannot be used a second time or after it expires.
  • Free key counters. A free key's requests are counted per minute and its registry lookups per UTC day under the key's ID. The free keys used from one IP address also count together toward a shared minute limit and a shared daily lookup cap, and the keys made from one IP address are counted per day (at most 3), all keyed by a hash of the IP address as described for lookup quota counters, never the address itself. Reports are counted for the current UTC month under part of the address hash, so that replacing a key does not restart the count, and also under the hash of the IP address, the same monthly count that reports made without a key use, so that several free keys used from one IP address share it. A counter is deleted when its window ends, or when the free key is deleted (see below), except the counters keyed by an IP address.
  • Deleting a free key. You can delete a free key yourself in two ways. At factlot.com/account, or with POST /v1/keys/free/delete, you give the address and we send one transactional email through Cloudflare Email Sending: a link that works once and expires after 30 minutes, with no key in it. We send it only if that address has a free key, and the answer is the same for every address, so nobody learns from it whether an address has a key and nothing is sent to an address that never asked for one. Opening the link only shows a button; pressing it deletes. Or, with the key itself, send DELETE /v1/keys/free with the key as the bearer token: no email is sent. Either way we delete the key, every key it replaced, the record of the address hash, the report counter kept under the address hash and each key's counters. The deletion email uses the same kind of records as the link email: a link record for 30 minutes, a marker of the address hash for 5 minutes (at most one deletion email every 5 minutes), and a marker that the link was used, held under a hash of its random ID and not linked to the address, for 13 months. These are not deleted by deleting the key, and neither are: a link email you already received, which stays valid until it expires; counters keyed by an IP address; usage records, which hold "free-key" and no key ID or address; report files, which are not linked to the address and are deleted after 24 hours; and Cloudflare's own request logs. If you cannot use either way, email contact@factlot.com from the address the key was issued to and we do it for you.
  • Other transactional email. Paid plans send up to three kinds of message through Cloudflare Email Sending, each only because of something you did and none carrying an API key. A welcome email, once, to the address you gave Stripe when a checkout completes: it names the plan and price, says the subscription renews monthly until cancelled, and gives setup steps and links to the account page and the API. We do not store that address unless you tick the box for optional emails described below. A sign-in link, when you enter an address under "Lost your key?" at factlot.com/account and Stripe has a customer with that address who has a FactLot subscription: it names each plan and has a link per subscription that works once, expires after 15 minutes and lets you issue a new key. A connect link, when an app connecting to the hosted MCP server asks for one for an address with a subscription: it names the app and has a link per plan that works once and expires after 10 minutes. Nothing is sent when no subscription matches, and the page answers the same either way. We look the address up in Stripe in memory, and keep a marker of a SHA-256 hash of the lower-case address (no secret added) for 5 minutes for the sign-in link and 2 minutes for the connect link, so that one address gets at most one such email in that time. We send no marketing email except the optional emails described next, and only if you ticked the box for them.
  • Optional emails (only if you tick the box). The free key form and the page you see after checkout each have a separate box, unticked, that says what is sent: up to 4 optional notes about a free key (one when a lookup leaves earlier roll years out, one if the key has not been used after 2 days, one when the daily limit is reached, and a summary after 7 days), or up to 2 about a plan (one if the key has not been used 1 day after you buy, and one after 7 days). Each note is sent at most once, never more than one a day, and carries our postal address and a link that stops all of them with one click, without signing in. You can also stop them by entering your address at factlot.com/account/stop, or by emailing contact@factlot.com. If you tick the box we record it only when you open the link in the free key email (so nobody can sign up another person's address), or, for a plan, when you save your choice on the page after checkout, using the address you gave Stripe. We then store, with your key or subscription, your email address (we cannot send without it), the time you ticked the box, a reference to your key's usage tally or your subscription, and the time each note was sent. That record, and the address in it, is deleted when you stop the notes, when you delete your free key, and after the key or plan has ended. When you stop, we keep one marker: the hash of your address described above and the time you stopped, and nothing else, so that you are never sent an optional note again, even if you later ask for a new key or tick the box again. Deleting a key does not delete that marker. The stop link holds the same hash of your address, signed so it cannot be forged, and does not expire; Cloudflare's request logs may hold it. While optional emails are on, a free key's registry lookups are also tallied by day, by tool and by state prefix under the key's ID, never the parcel or address searched, so that the summary can state them; the tally is deleted with the key. Between ticking the box on the free key form and opening the link, your address is held in the 30-minute link record. Optional notes go through Cloudflare Email Sending. Their legal basis is your consent, which you can withdraw at any time as described; withdrawing does not affect notes already sent.
  • Checkout return link. When you start checkout from a lookup or a property page, the address you searched (at most 120 characters of letters, digits and simple punctuation) or the parcel's ID can travel in the checkout's return web address, so that the page after payment, and the welcome email, link back to it. It holds no email address, key or name; Stripe's and Cloudflare's logs may hold it.

Billing

Stripe runs checkout and billing and collects what it needs to take payment: your email address, name, card or bank details, billing address, and a tax ID if checkout asks for one. Stripe handles these under its own privacy policy. In Stripe, FactLot can see your email, name and billing address as you entered them, your subscription status, your invoices, and your card's brand and last four digits. FactLot never sees or stores your full card number.

Email

If you write to contact@factlot.com, we receive your email address, your message and anything you attach. Cloudflare Email Routing forwards it to the operator's mailbox. If you reply to the free key email, your reply comes to the same mailbox and is handled the same way. Please do not send confidential leases or personal data by email.

GitHub

Issues and Discussions on GitHub are public and covered by GitHub's privacy statement. Anything you post there can be read by anyone.

What we do not collect

  • Request bodies, tool inputs and outputs, and documents. Document text is processed in memory to answer the request and is not stored or logged. The one exception is a report you build with report_create: the generated file is kept for 24 hours (see "The hosted API" above).
  • Request headers, other than reading the key to authorise the request.
  • IP addresses in usage records.
  • Cookies, tracking pixels or advertising identifiers.
  • Natural-person names in the registry. The registry holds commercial property and the organisations that own it. It is built to keep owners that are organisations and to exclude natural persons' names, and owner records a source withheld are never recovered or inferred. If a record names you as a person, or is wrong, email contact@factlot.com and we will remove or correct it.

We do not use your requests or documents to train models, and we do not build profiles of you.

Why we use it

  • To provide the service you asked for: answering requests, checking keys, applying your plan. This is needed to perform our agreement with you.
  • To send you the free key you asked for: the one link email described above. This is needed to perform our agreement with you. We do not use the address for anything else.
  • To keep the service working and fair: rate limits, quotas, abuse prevention and fixing errors. This is our legitimate interest in running a reliable service.
  • To bill you and keep tax records: needed to perform our agreement and required by law.
  • To answer you when you write to us, and to send notices about your plan, these terms or a security problem.
  • To send the optional emails you ticked the box for: your consent.
  • To plan capacity: counting requests by tool path, plan and status, with no IP address.

We do not sell personal information, do not use it for advertising, and make no automated decisions about you with legal or similar effects.

Your rights

Anyone can ask us to:

  • tell you what personal information we hold about you and give you a copy (access);
  • correct it (correction);
  • delete it (deletion);
  • give it to you in a portable, machine-readable form (portability); and
  • stop using it for a purpose you object to.

We give everyone the rights above. Where the California Consumer Privacy Act or the Texas Data Privacy and Security Act applies, they include the rights that law sets out.

California Consumer Privacy Act (as amended by the California Privacy Rights Act): the rights to know what personal information we collect, use and disclose; to delete it; to correct it; to opt out of its sale or sharing; and to limit the use of sensitive personal information. We do not sell or share personal information and do not use sensitive personal information, so there is nothing to opt out of or limit.

Texas Data Privacy and Security Act: the rights to confirm whether we process your personal data and to access it; to correct it; to delete it; to get a portable copy; and to opt out of targeted advertising, sale, and profiling that has legal or similarly significant effects. We do none of those three. If we decline your request, you may appeal by replying to our answer with the word "Appeal"; we answer an appeal within 60 days. If you are not satisfied with that answer, you can contact the Texas Attorney General.

We will not treat you differently, charge you more or give you a worse service for using any of these rights.

How to use your rights

Email contact@factlot.com from the address on your account, or include your API key ID from a response or your Stripe receipt. Never send us the key itself. A free key you can delete yourself, without writing to us: at factlot.com/account (we email a link to the address) or with DELETE /v1/keys/free and the key. If you cannot, write from the address you asked for it with and say so: we find its records by the hash of that address and delete them. We confirm who you are by replying to that address, answer within 45 days (once extendable by another 45 days if we tell you why), and charge nothing. An authorised agent may ask for you with your written permission.

Security

  • API keys are random, shown once, and stored only as a SHA-256 hash.
  • Every connection to factlot.com and api.factlot.com is encrypted with TLS.
  • We keep as little as possible: no request content, no documents, no IP addresses in usage records, and no card numbers.
  • Stripe handles all card data.

No system is perfectly secure. If a breach affects your personal information, we will tell you as the law requires. To report a vulnerability, see SECURITY.md.

Children

FactLot is a business service for people aged 18 or older. It is not directed to children, and we do not knowingly collect information from anyone under 18. If you believe a child has sent us personal information, email us and we will delete it.

International use

FactLot is run from the United States. Cloudflare serves requests from the data centre nearest you on its global network, and Cloudflare, Stripe and GitHub are United States companies. If you use FactLot from outside the United States, your information is processed in the United States.
