# Security audit, 2026-11-03

Pre-launch review of the FactLot repository before it is made public. Branch `security-audit`,
cut from `main` at `b4d11c9`. Line numbers in the findings refer to that base commit unless a
finding says otherwise.

## Scope

- **Repository history**: every commit on every branch and remote-tracking ref (`git log --all
-p`, 73 commits), for credentials and private data, before the repository goes public.
- **Hosted connector** (`packages/server`): authentication, rate limiting, request size and
  shape, CPU-bound input, timeouts, CORS, headers, error disclosure, OpenAPI, MCP, methods, and
  `/v1/usage`.
- **MCP server** (`packages/mcp`, stdio and the stateless HTTP use from the server).
- **Tool catalog and calculators** (`packages/tools`, `packages/calc`) and the Python SDK's
  `run_tool` and calculators, for input validation parity and unbounded cost.
- **Python registry tooling**: collector (`python/src/factlot/collector`), registry store and
  adapters, ingest (PDF/OCR subprocesses, review queue).
- **Supply chain and CI**: npm dependency tree, Python runtime dependencies, GitHub Actions
  workflows, Dependabot.
- **Docker image**: build, user, base, layers, healthcheck, read-only operation.

Out of scope: the hosting platform itself (DNS, TLS, WAF, logging pipeline), the factlot.com
site's host, third-party services the project will use later (npm, PyPI, model providers).

## Method

- History scan: a stdlib-only scanner (no secret scanner was installed) over the added lines of
  `git log --all -p`, with patterns for AWS, GitHub, Anthropic, OpenAI, Slack, Stripe, Google,
  npm, PyPI, SendGrid, Twilio and Vercel tokens, JWTs, PEM headers, URLs with passwords,
  `.env`-style secret assignments, and high-entropy (Shannon > 3.5 bits/char) string values
  assigned to key/secret/token/password names; plus every e-mail address and US phone number,
  sensitive file names across history (`.env`, keys, databases, `.npmrc`), deleted files, the
  strings in committed `.pyc` files, PDF metadata and form-field values, and commit author and
  committer identities. Data files (`registry/`, `spec/`, test fixtures, research `.jsonl`) were
  checked for owner-of-record and other natural-person names (data policy §3).
- Code review of the areas above, with each fix written test-first where a test could show it.
- Measurement: tool cost against input size in both SDKs (for example `calc_irr` at 40, 1,200 and
  5,000 periods), and the differential test on new long-series generators across seeds 1, 2, 3,
  7, 11, 13 and 17 (3,000 cases each) to look for crashes and divergence.
- `npm audit --omit=dev` and the full tree; a stdlib check that the Python package imports
  nothing outside the standard library.
- Docker: built the image and ran it with `--read-only --cap-drop ALL --security-opt
no-new-privileges`, open and keyed, and exercised it with `curl` (results under
  [Verification](#verification)).

## Summary

No credentials, private keys, or `.env` content are in the history. No critical issue was found.
The most serious issues were in what an agent or a publisher can make FactLot do: a single REST
call could block the hosted server's event loop for minutes (IRR over ~250,000 cash flows fits in
the 1 MiB body limit), and the collector followed redirects to any address, on a runner that held
a write token, with the response then published as a release asset. Both are fixed.

## Residual risks for a hosted deployment

The server is one process with in-memory state. A public deployment must add:

1. **TLS termination** in front of the container (load balancer or reverse proxy). Set
   `FACTLOT_PUBLIC_URL` to the `https://` URL, and `FACTLOT_TRUST_PROXY=1` only when every request
   arrives through that proxy (then the proxy must overwrite, not append to, client-supplied
   `X-Forwarded-*`). Add HSTS at the edge.
2. **An edge firewall or rate limit.** Limits here are per instance (N instances allow N × limit)
   and reset on restart; volumetric attacks and connection floods must stop before the process.
   Calculators are synchronous, so the input caps bound one call to ~0.3 s of CPU, but a flood of
   such calls needs edge limiting or more instances.
3. **Authentication.** Configure keys: with none the server is open by design. Keys are static
   (restart to rotate); there is no OAuth. Keep the admin key off client machines.
4. **Log retention and access.** The request and usage logs hold key names, routes, statuses and
   timings, never bodies, arguments or keys, but they are business records: ship them to a store
   with access control and a stated retention period (the usage log is the billing record). Stderr
   error lines carry only the route and the error name.
5. **Image hygiene.** Scan the image for OS CVEs in CI and rebuild when the pinned base is updated
   (Dependabot proposes it). Run with `--read-only --cap-drop ALL --security-opt
no-new-privileges`, and mount a writable volume only for `FACTLOT_USAGE_LOG`.
6. **The registry database** (`FACTLOT_REGISTRY_DB`) is opened read-only; keep the file outside
   the image and not writable by the server user.
7. **The collector** must keep running on an ephemeral runner with no cloud credentials; its
   address checks are skipped when an HTTP proxy is configured (the peer is then the proxy), so do
   not add a proxy that can reach internal networks.

## Addendum (2026-11-03, after the repository went public)

GitHub's dependency alerts on the public repository listed three development-only advisories
(`tmp` path traversal, high; `tmp` symlink write, low; `minimatch` glob amplification, medium).
Root `package.json` `overrides` now pin `tmp` to `^0.2.6` and `minimatch` to `^11.0.1`; `npm run
check`, `npm run build:mcpb` and `npm run test:e2e` pass with them. `npm audit --omit=dev`
reports 0. The one remaining advisory is `zod` 3 bundled inside `@anthropic-ai/mcpb`, the build
tool that validates the extension manifest at build time; no patched 3.x exists and the runtime
uses `zod` 4.6.7, which is not affected. Accepted until `@anthropic-ai/mcpb` updates.
