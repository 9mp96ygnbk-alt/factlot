# Tier 1 data quality, 2026-11-03

The Tier 1 registry files were audited, the defects the audit found were fixed in the adapters and the
pipeline, and the files were rebuilt. This page records what was measured, what changed, and what is still
wrong and why.

It is reproducible. The audit is `python -m factlot.registry.audit` (read only; tests in
`python/tests/test_registry_audit.py`); the repairs are `python -m factlot.registry.maintain` and the re-ingest
commands in [`scripts/registry/tier1-quality.sh`](../../../scripts/registry/tier1-quality.sh); every number below is
the audit's output on the built files:

```
python -m factlot.registry.audit registry.db --collected collected/ --reread --entity-names --out audit.json
```

## What the audit checks

Per source and per snapshot, from the registry file alone, and with `--reread` against the archived source file:

- **Counts.** Parcels the file holds, current and retired. With `--reread`, what the adapter yields when it is run
  again on the archived file after the commercial filter, the distinct APNs and distinct FactLot parcel IDs (two
  APNs that normalize alike collapse into one), and whether the registry holds exactly that. APNs that look like
  column headings are flagged: an earlier adapter's failure was a header row read as data.
- **Completeness.** For every parcel field, how many parcels have it; parcels with no situs address, no organisation
  owner, or a fact with no valid `as_of`.
- **Duplicates and conflicts.** Parcels with two different values for one single-valued fact from one document.
- **Implausible figures.** A year built before 1700 or after next year, an area of zero or over 500 million square feet,
  a negative value or one over $50 billion, a tax year before 2000, a category outside B, F1 and F2.
- **Privacy.** Owner-of-record facts that the current `is_organization` rule reads as a natural person. The policy number
  is zero, and the audit exits 1 if it is not.
- **Owner links.** Organisation-owned parcels, how many link to a registered entity, by rule and confidence, and why the
  rest do not; the review queue.
- **Citations.** Facts and links whose document is not a snapshot or not a SHA-256 content address, or that have no record
  locator, valid date or method; a source with no URL or licence; a parcel whose address or account is missing from its
  lookup table.
- **Age.** Days from each snapshot's `as_of` to the audit date (a warning above 400).

## What was fixed

### 1. Natural-person owner names were stored

Files built under an earlier, looser person rule held owner-of-record names that the current rule reads as natural persons:
Travis 65 of 17,944, Collin 10 of 13,174, Tarrant 5 of 30,732, Boston 1 (before the trust rule below), Philadelphia 114 (before
the trust rule) and a handful more in the Texas and Tier 1 files once the trust rule below applied (27 in the Texas file, 7 in the
Tier 1 file). `purge_person_owners` removed them, with their mailing addresses and any links; every Tier 1 file now audits at zero,
and the audit exits 1 if it finds one. The audit caught a regression of its own during the work: a first draft of the apostrophe change
read `PRESIDENTIAL OWNERS'CORP` as a person, which is why `is_organization` keeps an apostrophe as a word separator while
`normalize_name` drops it.

Two rule changes came out of it, in opposite directions:

- **A trust named for a person is a person** even when its name holds PROPERTY or REALTY (`DOE JANE SEPARATE PROPERTY TRUST`,
  `SMITH JOHN A REVOCABLE REALTY`): a marker such as SEPARATE PROPERTY, REVOCABLE, LIFE ESTATE or ESTATE OF makes it a person unless
  the name also has a company word (LLC, LP, INC, ...). Business trusts (`CAMDEN PROPERTY TRUST`, Boston's `... REALTY TRUST`)
  are unchanged.
- **A spaced `L P` is a partnership when the name has evidence.** The rule that reads `GARCIA MARIA L P` as a person's initials also
  dropped real partnerships, because Travis, Philadelphia and Boston write L.P. as `L P`. A name with a number (`400 NUECES L P`) or a
  property or business word (`BROAD PLAZA L P`) is now a partnership; `GSGB L P` and `LOPEZ MARIA ELENA L P` stay unread, which loses a
  partnership's owner name but never stores a person's. Re-ingesting restored the owners the first rule had dropped.

### 2. Three Texas counties could not be linked at all

Tarrant, Travis and Collin were built into standalone files with no entity registry, so none of their 61,850
organisation-owned parcels had a link, and the Harris and Dallas file's links carried the oldest basis text (no jurisdiction rule,
no standing rule). All five counties are now in one file with the Comptroller's 3,272,057 entities, and owner links were
re-derived under the current rules: **116,490 of 152,051 organisation-owned Texas parcels (76.6%) link,
every link citing its rule and confidence** (Harris and Dallas alone: 66,092 of 90,093, 73.4%, before; 69,153 of
90,178, 76.7%, after).

### 3. The Travis snapshot was stale

The registry held the July certified roll (supplement 0, 2026-07-18) although the collector had archived supplement 3 (run date
2026-10-06, a full re-export) on 2026-11-02. Both are loaded now; the October roll is current, the July facts are history, and the one
parcel the supplement drops is retired. `tx-travis-cad` is 30,555 current parcels.

### 4. Colorado entity names carried a status history

`entityname` in the Colorado file ends in the Department's history of the entity's standing for 1,871,772 of its 3,132,613 rows
(`ACME INC, Delinquent January 1, 2025`; `X INC Reinstated 2004, Dissolved June 29, 2011`). It was kept as the legal name, so an owner of record written
`ACME INC` never matched. The adapter now strips it (the status column already says it) and `Registry.rewrite_entity_names` applied the
fix in place. Denver's link rate moved from 83.98% to 85.75%.

### 5. New York City owner names were broken mid-word

The NYC owner field is two 40-character halves joined by a space, so a longer name is cut wherever the 40th character falls:
`... LIABILITY COMPA NY`, `... REVOCABLE LIVING TRU ST` (9,436 of 461,249 rows). The adapter now closes a break when the two fragments form a word the
file's unwrapped names use more often than the first fragment alone. NYC's link rate moved from 73.17% to 75.59%.

### 6. Owner-name normalization

`normalize_name` (Python and its TypeScript mirror, with 30 shared vectors that both languages now run) additionally drops apostrophes
(`O'REILLY` and `OREILLY`), removes what a roll appends to an owner (`ET AL`, a `DBA` trade name, a dangling `&` or `THE`: `AVR HIDDEN RIDGE I LLC &`),
reads `NO 1` as `1`, runs consecutive initials together (`W.G.G. PROPERTIES` and `WGG PROPERTIES`), and spells common abbreviations one way (`PPTIES`/`PROPERTIES`,
`CTR`/`CENTER`, `AVENUE`/`AVE`). Ambiguous abbreviations (`ASSOC`, `INV`) and anything that could be a person's initial (directions) are left alone, and near matches
stay in the review queue. Measured on the Texas file, 4,605 of its 116,490 links exist only under the new key. The name index was
re-keyed in place (`Registry.rebuild_name_index`: 171,219 of 3.27 million Texas keys and 700,784 of 9.6 million Tier 1 keys changed) and the review queue
re-keyed with it.

### 7. Mecklenburg land area

On 139 parcels the Assessor's `legalacres` holds square feet, and 37 of them read as over 500 million square feet after the conversion
(37,330.92 "acres" beside a 0.858-acre polygon). The adapter reads such a figure as square feet when it agrees with the polygon, and uses the polygon otherwise.
On 21 condominium units the field holds a unit's square footage beside a polygon that is the whole complex; those units get no land area. The audit's
implausible-area warning for Mecklenburg went from 37 parcels to none.

### 8. Review queue and re-ingest

- `link_owners` drops a pending review candidate for a name that now links (1,033 + 457 + 571 rows here); decided rows are never touched.
- Re-ingesting a snapshot used to leave the old fact beside the new one if an adapter fix changed a value. It now replaces the facts an earlier
  run wrote for that snapshot and the adapter no longer yields, and links derived from a replaced owner; an unchanged file still writes nothing.
  The fixes above depend on it (NYC owners, Mecklenburg areas, restored `L P` owners).

### 9. Counts and links in the documentation

The index said Tarrant had 37,292 parcels (the commercial extract; the full set holds 45,976), Harris, Dallas and Tarrant linked to
review records that do not exist (they point to `texas-sources.md`), and the registry README still gave the first Texas run's owner counts.
These were corrected, and each source's review record notes what changed.

### Things the audit checked that were already clean

Every source's adapter, run again on the archived file, yields exactly the parcels the registry holds (all 5 Texas
sources, NYC, LA's four pieces, Denver's two files, DC, Hennepin, Mecklenburg, Boston, San Francisco and Philadelphia's 30 pieces), with no
APN that looks like a header and none that collapses into another; all five entity files hold exactly the entities the adapter yields (the rows it skips have no registry number);
no fact lacks a locator, a valid date, a method or a snapshot, no link lacks a basis, every snapshot is a SHA-256 content address, and every parcel with an address
or an account is in its lookup table.

## What remains, and why

### Owners that cannot link

- **Governments, school districts, railroads and banks are not in business registries.** Across the Texas, NYC, Denver and DC files, 6,500
  parcels belong to a city, county, district, authority or state (`DALLAS CITY OF`, `FORT WORTH ISD`, `TEXAS STATE OF`); banks and railroads are likewise outside the
  Comptroller's franchise-tax file. They are public record, they just have no entity to link to.
- **States with no entity registry loaded.** Hennepin (15,436 organisation-owned parcels) and Mecklenburg
  (19,676) have no Minnesota or North Carolina registry (gated: purchase), and neither do Boston (9,255)
  or Philadelphia's owners (a Pennsylvania registry is loaded in the Tier 1 file, but Philadelphia is a gated source and lives in its own file, so it was purged
  of persons and not re-ingested or linked). The 159 and 247 links in Hennepin and Mecklenburg are entities registered in another state.
- **No owner names in the source.** Los Angeles (203,179 parcels) and San Francisco (19,048) publish none.
- **Owners with no exact registered name.** After the rules above, 41,270 parcels in the Texas, NYC, Denver and DC files have an owner whose normalized name
  matches no entity (typically the assumed or abbreviated name of a company, or a name the roll truncated at its field width) and
  19,659 more have near matches waiting for a reviewer. There is no auto-accept.

### The review queues need a person

7,986 pending candidates in the Texas file and 24,327 in the Tier 1 file. About half of the Tier 1 queue (Hennepin and Mecklenburg:
11,959 rows) are candidates from other states' registries for owners in states
with no registry of their own; they are rarely right and a reviewer will mostly reject them. Restricting fuzzy candidates to plausible states, as exact links
already are, would shrink the queue; it was not changed here because it alters the review model.

### Source limits, not defects

- **Situs addresses.** Los Angeles leaves 10,223 parcels (5.0%) without one,
  Mecklenburg 2,921 (12.3%, including 661 apartment parcels), Collin 149. Tarrant publishes a street line with no city or ZIP, and Travis leaves the situs city blank on 59% of properties. Nothing is inferred.
- **Values.** Dallas has no appraised value distinct from market value, San Francisco and Los Angeles publish assessed values only (no market value), Los Angeles no land area,
  Philadelphia no tax year. The fields are left empty.
- **Implausible figures in the sources** are few and are reported by the audit as warnings, not repaired: a year built outside 1700 to 2028 on
  13 parcels, and 1 NYC area.
- **Boston** reports `as_of` 2025-01-01, the valuation date of its FY2026 roll; it is the current roll (FY2027 is due around December 2026) and the age warning is expected.
- **Collector file names** such as `csv` (Los Angeles, Denver) and `ViewPDFs.aspx` (Dallas) appear in citations as the document's title; the SHA-256 and URL are exact.
- **Entity names that read as persons** (`--entity-names`): 117,357 Comptroller,
  232,575 Colorado, 71,890 New York, 88,673 Pennsylvania and
  41,312 DC registrations have no organisation word in their name. A sample shows ministries, clubs, `...Chiropractic, P.C.` and
  similar, which are registered legal entities and not natural persons, so this is informational and no rule acts on it.

### Open items

- Philadelphia stays gated; its file was only purged. Whether to load it into the Tier 1 file (and link it to the Pennsylvania registry) is the terms decision.
- Registry files not rebuilt here need `python -m factlot.registry.maintain registry.db --all` after this change: the Tier 2 file, and the published DC sample
  if its name search should honour the new keys (a name with an apostrophe, an `ET AL`, `STREET` or run-together initials searches under the new key).

## Method notes

- The audit read the archived source files in the collector's `collected/` directory (no network, no new download, no request to any host).
- The built files were updated in place (the Texas file, the Tier 1 file, and the standalone Boston and San Francisco files; Philadelphia's only to purge persons;
  the standalone Travis, Collin and Tarrant files were read, not changed, and are now superseded by the Texas file).
  Two jobs were killed and restarted mid-run (a name re-keying that was scanning an unindexed table per row, and one started before a later normalization change); SQLite rolled
  each back, and the final runs were complete.
- The `before` figures for Boston, Philadelphia and the Tier 1 file were measured before the trust rule existed; their purges under it are stated in the text, not in the table.
- No gated source was touched beyond the Philadelphia purge. No account, form, purchase or message.

The reports behind every number are in [audit-2026-11-03/](audit-2026-11-03/).

## Re-running

```
export COLLECTED=/path/to/collected TEXAS_DB=texas.db TIER1_DB=tier1.db
scripts/registry/tier1-quality.sh texas-ingest texas-maintain tier1-ingest tier1-maintain
python -m factlot.registry.audit texas.db --collected "$COLLECTED" --reread --entity-names --out texas-audit.json
python -m factlot.registry.audit tier1.db --collected "$COLLECTED" --reread --entity-names --out tier1-audit.json
```

Every step is idempotent. Re-ingesting a snapshot already in a file replaces what an earlier run wrote for it (an adapter
fix takes effect) and writes nothing if the adapter yields the same facts. A registry file built before this change (the Tier 2 file) or
a published sample needs `python -m factlot.registry.maintain registry.db --all` once, because
name keys changed (the index is re-keyed in place; no source file is read).
